# Episuite product and code review

18 November 2026

## Implementation update

The follow-up implementation adds daily outcomes, explicit next actions, end-of-day carry/schedule/defer choices, cue/minimum/obstacle habit plans, planned rest and rest undo, recent opportunity summaries, weekly reviews, quiet focus, focus preparation and distraction reset actions, and device-private trials with retention and deletion.

The backup path now shares a 64 MiB UTF-8 byte limit, sends portable exports without building a second indented copy, validates imports before making a recovery copy, and restores large Unicode fixtures onto a clean workspace. Dialog headings render through textContent. Offline capture uses workspace-scoped IndexedDB records and individual acknowledgments. Calendar connection changes have a revision check and merge only sync metadata. Owner data files use restrictive creation modes on supporting systems, mutation methods are explicit, and the Zepp day feed supports an optional read token.

Compose now publishes on loopback by default. Reachable clients still have owner access to the main workspace. Tailscale or authenticated-proxy deployment remains an operator setup step. Speech-free focus offers a reminder to pause audio and device controls remain responsible for enforcement across apps.

The code now separates request parsing and persistence, expired-timer advancement, method validation, device persistence, and productivity helpers. Playwright is a locked development dependency and browser scripts share a portable runtime selector. Existing user reward settings are preserved. Fresh workspaces start with fixed payouts, quiet focus, and streak displays off.

Verification includes 90 passing unit/integration tests and browser checks for the new workflows, concurrent offline capture, Social/PWA, Life board, and phone/desktop page layouts. The large-history profile measured a 4.26 MB synthetic three-year workspace at roughly 89 ms startup, 182 ms full sync, 339 ms median capture write including state response, and 138 ms for seven daily metric queries on this machine. Compact persistence, set/map lookups, and count aggregation reduce avoidable work. JSON storage remains in use for this single-owner app. SQLite migration and history partitioning remain conditional scaling options if real workloads require them.

The findings below record the original snapshot. Physical phone/watch behavior, the real deployment boundary, container execution, and long-term behavioral outcomes still need verification in use.

Episuite is strongest when it helps you start one meaningful task, keep your place during an interruption, and return with a clear next action. Its two-minute start, shared timer, quick capture, and optional session receipt already cover much of that loop. The biggest opportunity is to make those actions easier to reach on an ordinary day, then measure whether they lead to useful work outside the app.

Fix backup round-tripping and make the owner access boundary clear first. Then make the everyday experience quieter and give each important habit an actionable cue and an easy way back after a miss. Background audio and unwanted browsing are good candidates for small, private experiments because the relevant questions are personal and task-specific.

## Engineering and product findings

**High · Valid exports can become unrestorable.** Export serializes the full portable workspace, with no corresponding size check. The browser rejects import files above 5,000,000 bytes and the server caps request bodies around the same size. Histories and captures accumulate, and the workspace can include a background image or an archived legacy payload. Make every supported export round-trip. Use a dedicated, bounded import path with an actual byte count and correct UTF-8 decoding. Set the bound from realistic workspace fixtures and handle larger archives explicitly. Add a large round-trip case, test multibyte notes, and verify a restore onto a clean server. [Export](episuite/server.mjs#L113) · [Body reader](episuite/server.mjs#L65) · [Import picker](episuite/public/app.js#L610)

**High when reachable outside a trusted owner boundary · Any client with direct access is effectively the owner.** Compose publishes on all host interfaces by default, and the main workspace API exposes the owner state, export, and write operations without identity verification. The browser origin and fetch-metadata checks serve a different purpose. If you use Tailscale Serve or an authenticated proxy on the host, bind the published port to loopback and test that devices can reach the authenticated endpoint while the direct port is inaccessible. For intentional LAN use, document who can reach it. Consider scoped authentication for the watch feed and preserve the dedicated automation and redemption contracts. Keep personal-data providers opt-in and add a notification preview showing which fields leave the server. Commitments can send names and locations, and rare payouts can send task titles. [Compose](episuite/docker-compose.yml#L5) · [Routing](episuite/server.mjs#L66) · [Watch feed](episuite/server.mjs#L122) · [Notifications](episuite/server.mjs#L300)

**High · Task history titles can be rendered as markup.** The history dispatcher passes the task title to a dialog helper that interpolates its title directly into HTML. Several other call sites escape dynamic titles before calling the helper. A routine title containing angle brackets should display literally. Make the helper accept plain heading text, then audit callers for double escaping and render trusted rich content through a separate explicit path. Add a browser check for literal rendering of special characters. This is a source finding. [Dialog renderer](episuite/public/app.js#L308) · [History action](episuite/public/app.js#L415)

**Medium · The offline capture queue can overwrite newer entries.** Sync reads one array, awaits each network request, then writes that older array back after removing the acknowledged entry. Another tab, another sync, or a capture made during the await can change the queue in between. Server-side ID deduplication is already useful. Keep it and store each pending capture under its own key in IndexedDB, then delete only the acknowledged record. Scope pending work to workspace identity and exercise two tabs plus reconnect while queuing. Visible pending counts and explicit sync errors would make the behavior easier to trust. This is a source finding. [Capture and load logic](episuite/public/app.js#L95) · [Server deduplication](episuite/server.mjs#L212)

**Medium · An in-flight calendar sync can overwrite connection edits.** The server snapshots calendar configuration, waits for CalDAV, then checks only the URL before replacing the calendar object. A username or password update to the same URL can be reverted when the sync commits. Give connection settings a revision and keep sync metadata separate from credentials. Use a delayed mock response to exercise a credential edit mid-sync, and surface when a remote operation succeeded but local reconciliation must be retried. This is a source finding. [Configuration write](episuite/server.mjs#L250) · [Calendar commit](episuite/server.mjs#L281)

**Medium · Whole-workspace state makes growing history expensive.** The server clones and rewrites the workspace on mutation, compares records, and scans session and task histories. The client receives a full sanitized state after changes, caches the snapshot in local storage, and rebuilds the app shell with HTML. ETags hold down unchanged traffic, which is valuable. Profile startup, a task check-off, full sync, and storage size against synthetic small and multi-year workspaces. Then isolate the active workspace from long histories and large media, render changing regions selectively, and report when an offline snapshot could not be refreshed. Keep JSON if measurements are acceptable. Consider SQLite if whole-file cost or transactional operations become a measured constraint. [Write path](episuite/server.mjs#L39) · [Conditional state](episuite/server.mjs#L106) · [Client rendering](episuite/public/app.js#L114)

**Medium · Code and verification are getting harder to change safely.** The server route mixes dispatch, input handling, side effects, and persistence. The web entry point combines page templates, shared state, integration settings, document-wide handlers, rendering, and timer/audio lifecycle. Long lines make review harder. Existing modules for Social, engagement, and calendar provide a path forward. Extract state transport and capture persistence first, then timer advancement and domain-specific routes. Use explicit HTTP methods and shared input validation, and put browser test dependencies and executable selection under documented configuration. The root README still describes a dependency-free app and a hand-picked test command, while the package has locked runtime dependencies and a complete test command. Make one authoritative setup and verification entry point. [Server dispatch](episuite/server.mjs#L126) · [Web entry point](episuite/public/app.js) · [Browser setup](episuite/scripts/check-life-board-browser.mjs#L9) · [Root guide](README.md) · [Package scripts](episuite/package.json)

**Medium · The app can pull attention back to itself.** New workspaces default to gamification on and random task rewards on. The payout function uses a long-tailed distribution and the notification layer can announce rare payouts when enabled. It also makes an identical random draw determine coins independently of the task's base award, even though the editor labels difficulties with fixed coin amounts. Streaks are visible on task rows and the Life board, while some onboarding and progress copy emphasizes no streak to protect. I would default new workspaces to predictable, quiet feedback, make streak presentation optional, and keep existing users' choices. Ask whether changing the defaults helps the owner finish important work and close the app. [Initial settings](episuite/public/domain.js#L12) · [Reward defaults](episuite/public/reward-events.js#L1) · [Coin calculation](episuite/random-rewards.mjs#L4) · [Task streaks](episuite/public/app.js#L199)

## Behavioral research and implications for Episuite

### Habit formation and app usage

**Repeat a specific action after a cue that already happens.** Lally and colleagues studied everyday behaviors repeated in a consistent context. Estimated time to near-plateau automaticity varied widely, from 18 to 254 days among the fitted cases. One missed opportunity had little effect in that study. Habit automaticity is the ease with which the context brings the behavior to mind. A check mark measures a recorded completion. Episuite already has recurring tasks and a workspace-level reason and cue. Add a cue linked to each selected habit, one minimum version, and a way to change the cue when circumstances change. Show recent opportunities followed through, with planned rest outside the denominator. [Lally et al., 2010](https://doi.org/10.1002/ejsp.674) · [Stawarz, Cox and Blandford's habit app study](https://discovery.ucl.ac.uk/id/eprint/1468224/)

**Use if–then plans to cross the gap between intention and action.** Gollwitzer and Sheeran's meta-analysis found positive effects on goal attainment across diverse interventions. The estimate is an average across settings. A useful plan is “After I put down my morning coffee, I open the draft and work on one paragraph.” An obstacle plan might be “If I have only five minutes, I open the draft and leave one line for later.” Surface the plan where a start is possible. Keep the two-minute timer as a low-cost design choice whose usefulness can be tested on the owner's work. [Gollwitzer and Sheeran, 2006](https://doi.org/10.1016/S0065-2601(06)38002-1)

**Design for useful action and a graceful exit.** In experiments reviewed by Deci and colleagues, some expected tangible rewards reduced later voluntary engagement, while positive feedback could help. Gamification experiments show that different mechanics can affect different aspects of motivation. Effects depend on the task and reward. Episuite can preserve optional play and keep “saved,” “one paragraph drafted,” and “your next action is ready” as the primary feedback. Access to ordinary rest should stay independent of coins. Use reopening after a lapse as a secondary success measure, and keep the main measure tied to meaningful work. [Deci, Koestner and Ryan, 1999](https://pubmed.ncbi.nlm.nih.gov/10589297/) · [Sailer et al., 2017](https://www.sciencedirect.com/science/article/pii/S074756321630855X)

### Attention, interruptions, and always-on audio

**Interruptions can cost attention even when the phone stays untouched.** Stothart and colleagues found that receiving a phone notification disrupted performance on their attention task. Leroy's task-switching research suggests an unfinished task can retain attention. Leroy and Glomb found that a brief plan for resuming helped in their interruption experiments. Episuite already captures interruptions and stores a next move after a completed session. Make “Save where I am” available while pausing or switching as well. Offer an optional pre-focus reminder to silence notifications, allow important exceptions through device settings, and suppress Episuite's own nonessential alerts during focus. A separate randomized study found attention benefits from temporarily blocking mobile internet on smartphones. That intervention was broader than a focus prompt and does not establish an equivalent effect for Episuite. [Stothart et al., 2015](https://pubmed.ncbi.nlm.nih.gov/26121498/) · [Leroy, 2009](https://doi.org/10.1016/j.obhdp.2009.04.002) · [Leroy and Glomb, 2018](https://doi.org/10.1287/orsc.2017.1184) · [Castelo et al., 2025](https://pubmed.ncbi.nlm.nih.gov/39967678/)

**Intelligible speech competes especially with language-heavy work.** In Vasilev and colleagues' eye-tracking experiments, understandable background speech increased rereading, and comprehension suffered when rereading was prevented. A separate meta-analysis found small average reading effects from background sound, with intelligible speech particularly disruptive. This directly informs reading. Applying it to drafting, studying, or debugging that involves interpreting language is a reasonable hypothesis. The studies do not establish permanent damage from podcasts or a need for silence while walking or doing routine chores. Episuite could offer a speech-free work preset and allow silence, its existing non-speech soundscapes, or normal audio to suit the user and task. Compare output and effort in similar sessions. [Eye-tracking experiments](https://pubmed.ncbi.nlm.nih.gov/31436455/) · [Reading meta-analysis](https://doi.org/10.1177/1745691617747398)

**Treat “always on” as an experience you can observe.** It might mean finding it uncomfortable to start without audio, noticing extra rereading, or feeling mentally occupied through breaks. Wilson and colleagues found that many participants disliked a brief period spent alone with their thoughts. Recovery research distinguishes mental detachment, relaxation, and control over leisure. A micro-break meta-analysis found small improvements in vigor and fatigue, with less clear overall performance benefits. These findings support offering choice. Try a two-minute walk, a stretch, or a drink without adding new content, then notice how ready you feel to return. Podcast time can still be deliberate leisure. [Wilson et al., 2014](https://pubmed.ncbi.nlm.nih.gov/24994650/) · [Sonnentag and Fritz, 2007](https://pubmed.ncbi.nlm.nih.gov/17638488/) · [Albulescu et al., 2022](https://doi.org/10.1371/journal.pone.0272460)

### Pornography use and attention

**Distinguish the time a behavior takes, attention drawn to cues, and a clinical problem.** In a lab study, people with compulsive sexual behaviors showed greater early attentional bias toward explicit cues than a comparison group. A systematic review of 21 experimental studies reported associations involving cue bias, inhibition, working memory, and decision-making in studies relevant to problematic pornography use. Tasks and samples varied, participants were predominantly young heterosexual men, and the findings do not establish a general loss of attention from ordinary pornography consumption or predict its effect for a particular user. A randomized seven-day abstinence study in regular users found no overall effect on withdrawal-related outcomes. It did not test the recovery of everyday attention. WHO clinical guidance emphasizes persistent impaired control and significant distress or impairment, with distress solely from moral disapproval insufficient. [Mechelmans et al., 2014](https://doi.org/10.1371/journal.pone.0105476) · [Castro-Calvo et al., 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8080450/) · [Fernandez et al., 2023](https://doi.org/10.1007/s10508-022-02519-w) · [WHO ICD-11 clinical descriptions](https://iris.who.int/handle/10665/375767)

**Build around the user's chosen boundary and the next useful action.** If browsing is displacing intended work or sleep, the concrete product questions are when it happens, what was displaced, and what would help the user switch back sooner. A generic opt-in plan could be “If I open an unrelated site during this block, I close it, stand up briefly, then return to the next step.” Offer a manual reset or an optional link to existing device controls. A browser page can offer the plan, while enforcement across other apps belongs to the device or a separately authorized integration. Keep the app's personal experiment useful with coarse categories such as “unplanned browsing” and an optional task outcome. Store no URLs, searches, or explicit descriptions for this workflow. Give experiment data deletion and retention controls, omit it from outward notifications and automation, and keep it out of ordinary backups and cached workspace snapshots by default. The current Android interface redeems purchased time. It does not identify distractions or enforce a behavior plan. [Screen-time contract](episuite/SCREEN-TIME-API.md)

## A two-week owner trial

Pick one recurring type of work whose output is visible, such as drafting sections, reading and summarizing a set of pages, or making progress against a defined coding task. Choose one outcome per planned block. For the first few comparable blocks, work as usual. For the remaining blocks, alternate or randomly assign your usual background audio and a speech-free condition on similar tasks at similar times. Keep session length and task difficulty roughly comparable. An optional non-speech condition can be a later comparison if silence feels distracting.

Record only what you will use. Start within ten minutes of the planned cue, outcome reached or advanced, and one optional friction rating are enough. For reading, a short unaided summary can reveal a difference missed by a stopwatch. For writing or coding, record what moved forward rather than words or lines alone. Track whether sessions were skipped so the apparent benefit is not driven by omitting difficult days. The ten-minute window is an example success measure.

In a subsequent trial, change one more thing. Use the private reset plan during the part of the day where unplanned browsing usually displaces something you value. Measure return time or whether you protected the intended work or bedtime. Keep the data coarse and the trial voluntary. Mark exceptions such as unusually hard work, poor sleep, or a deadline. Two weeks can help decide what is worth keeping or adjusting for the owner. It is too short to estimate long-term habit automaticity or draw clinical conclusions.
